# 単純ハンドシェイクで正当な読み取り時刻を受理する

- Created: 2026-11-25
- Completed: {YYYY-MM-DD}
- Branch: feature/fix-handshake-time2
- Polished: 2026-11-25

## 目的

RTMP の単純ハンドシェイクで、相手の読み取り時刻が非ゼロでも、正しいエコーを受理する。

## 現状

`rtmp_handshake` の `RtmpServerHandshake::handle_phase_p2` と `RtmpClientHandshake::handle_phase_p1` は、受信した C2 / S2 を、自分が送った S1 / C1 と全バイト比較する。このため `time2` だけが異なる正当な応答を `InvalidData` として拒否する。

[Adobe RTMP 仕様（2012 年 12 月版）§5.2.3](https://veovera.org/docs/legacy/rtmp-v1-0-spec.pdf#page=8) では C1 / S1 の第 2 フィールドはゼロ欄である。[§5.2.4](https://veovera.org/docs/legacy/rtmp-v1-0-spec.pdf#page=9) では C2 / S2 の同じ位置に、相手の第 1 パケットを読んだ時刻 `time2` を入れる。先頭の時刻と乱数欄はエコーするが、読み取り時刻はエコーではない。

### 再現条件

1. サーバーには有効な C0 / C1 を渡し、サーバーが返した S1 を使って、エコー時刻と乱数欄が一致する C2 を組み立てる。C2 の `time2` を非ゼロにして渡す。
2. クライアントが生成した C1 を使って、エコー時刻と乱数欄が一致する S2 を組み立てる。S2 の `time2` を非ゼロにし、有効な S0 / S1 に続けてクライアントに渡す。
3. どちらも `feed_recv_buf` は `InvalidData` を返し、`is_recv_complete()` は真にならない。

## 設計方針

- `rtmp_handshake` で、読み取り時刻だけを両方向の一致検査から外す。エコー時刻・乱数欄の検証、パケットが揃うまで待機する挙動、送信内容とハンドシェイクの順序は維持する。
- 両方向の `feed_recv_buf` の公開説明を更新し、エコー時刻と乱数欄だけを照合することを明記する。シグネチャは変更しない。
- `prop_rtmp_handshake` の既存の不一致テストは `time2` まで変更対象に含めている。非ゼロの `time2` を使ったうえで、不一致を作る対象をエコー時刻または乱数欄に限定する。

## 完了条件

- クライアントとサーバーは、エコーが一致していれば非ゼロの `time2` を含む応答を受理する。応答を分割した場合も、最後の受信で完了を確認できる。
- 読み取り時刻が非ゼロでも、エコー時刻だけが異なる場合と、乱数欄だけが異なる場合を、両方向で引き続き拒否する。
- 上記を両方向の公開 API の性質テストで検証する。
