# 配信サンプルの起動ログに RTMP URL 全体を出力しないようにする

- Created: 2026-11-23
- Completed: {YYYY-MM-DD}
- Branch: feature/fix-hide-publish-url-in-logs
- Polished: {YYYY-MM-DD}

## 目的

RTMP URL に認証情報や配信先固有の値が含まれる場合でも、配信サンプルの起動ログや引数のエラー出力に残らないようにする。

## 現状

- 配信サンプルの `main` は、配信処理の開始前に `RtmpUrl` を `Display` で整形して標準出力へ書き出す。整形結果には保持した `app` と `stream_name` が含まれ、クエリも省略されない。
- `--url` または `-u` の解析に失敗すると、`noargs` の `InvalidOpt` が元の引数を保持し、標準エラー出力に URL 全体を含める。`RtmpUrl` が入力値を含まないエラーを返した場合も同じである。

## 設計方針

配信サンプルの起動ログに URL 全体を表示しない。URL 引数の解析に失敗した場合は、無効なオプションを値なしで示し、元の URL や入力値を含み得る解析エラーを出力しない。接続に使用する値と、ライブラリの `RtmpUrl` の解析・整形契約は変更しない。

## 完了条件

- 正常な引数での起動時の出力に、入力由来の URL 全体、`app`、`stream_name`、クエリが含まれない。
- 無効な URL 引数は従来どおり失敗し、標準エラー出力に URL 全体や認証情報などの入力値を含めない。
- 機密情報ではない合成入力を使い、外部接続を必要とせずに正常・異常の両経路を検証する。
