# AMF の参照解決で指数的にメモリを消費する問題を修正する

- Completed: {YYYY-MM-DD}
- Branch: feature/fix-amf-reference-amplification

## 目的

AMF0 / AMF3 の参照解決で、小さな入力から指数的に大きな値が構築される問題を修正し、リモートからメモリと CPU を枯渇させられないようにする。

## 現状

- `src/amf3.rs` の `Decoder::decode_complex_type` は、複合型の参照を解決するときに参照先の `Amf3Value` を `clone()` する。複合型テーブルへの登録時にも `value.clone()` を行う。
- `src/amf0.rs` の `Decoder::decode_reference` も同様に、参照先の `Amf0Value` を `clone()` する。
- `Amf0Value` / `Amf3Value` は `Vec` と `String` を所有するため、`clone()` はディープコピーになる。
- 参照は仕様上有効であり、参照先はすでにデコード済みで循環していない。そのため、既存の循環参照検出を通過する。
- 「要素数 2 の配列の 1 要素目に子配列をインラインで置き、2 要素目にその子配列への参照を置く」構造を 1 段深くするたびに、デコード結果のノード数が約 2 倍になる。1 段は 5 バイト、葉は 3 バイトで、深さ n の入力は 5n + 3 バイト、ノード数は 2^(n+1) - 1 になる。
- 深さ 24 の入力は 123 バイトで 33,554,431 ノードになる。`Amf3Value` 1 個を 64 バイトとすると返り値の enum だけで約 2 GiB になり、各 `Vec` のヒープ確保と複合型テーブルに保持される複製を含めるとさらに大きくなる。
- AMF3 の入力は `09 05 01`（要素数 2 の配列と連想部の終端）、子配列、`09 <子への参照>`、葉 `09 01 01` の繰り返しで作れる。AMF0 でも同様の構造が作れる。到達経路は AMF3 の Data / Command メッセージ、または AMF0 の Command / Data 内の AVM+ marker（0x11）。

### 再現条件

1. 深さ n の AMF3 入力を組み立てる。各段は `09 05 01`、子配列、`09 ((index + 1) << 1)` の参照、葉は `09 01 01`。
2. `Amf3Value::decode` でデコードし、結果のノード数を数える。

期待は入力サイズに比例したメモリ使用、または上限超過を `ErrorKind::InvalidData` で拒否すること。実際は 2^(n+1) - 1 ノードを構築する。

## 設計方針

- 参照を値として複製するのではなく、同一性（`Rc` / アリーナ / インデックス参照）で扱うことを第一候補とする。ただし公開型 `Amf0Value` / `Amf3Value` の変更は破壊的変更になるため、影響範囲を整理する。
- 公開型を変えない場合は、デコード中に展開ノード数の上限を設け、超過時に `ErrorKind::InvalidData` を返す。上限は入力サイズから算出する固定値ではなく、実装が保証できる最大ノード数として定義する。
- どちらの方式でも、入力サイズに比例した計算量・メモリ量でデコードが完了することを設計上の不変条件とする。
- 参照の入れ子による増幅を検出する回帰テストを追加する。既存の PBT と fuzz は参照を生成しないため、この問題を検出できないことをテスト方針に明記する。

## 完了条件

- 参照を入れ子にした入力で、展開ノード数が上限を超えた場合に `ErrorKind::InvalidData` を返す、または同一性で扱うことでメモリ消費が入力サイズに比例する。
- 参照を含まない既存の AMF0 / AMF3 のデコードに回帰がない。
- 深さ 10 程度の増幅入力で、入力が 5n + 3 バイト、ノード数が 2^(n+1) - 1 になることを確認するテストを追加する。
- 上限値とエラー種別がドキュメントに記載されている。

## 解決方法

1. `src/amf3.rs` と `src/amf0.rs` の参照解決を、ディープコピーしない表現に変更する。公開型を変える場合は `Rc` などの導入と利用側の影響を整理する。
2. 公開型を変えない場合は、デコーダに展開ノード数のカウンタを追加し、上限超過時に `ErrorKind::InvalidData` を返す。
3. 参照を入れ子にした回帰テストを追加する。
4. `CHANGES.md` に CHANGE または FIX として記載する。
